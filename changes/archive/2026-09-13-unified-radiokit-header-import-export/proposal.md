# Proposal: Unified RADIOKIT.h Header Generation and Multi-Format Project Import

## Problem Statement
1. **Incomplete Header from API**: The `GET /api/designs/<id>/header` endpoint currently returns only the generated C++ code portion without the top `/*__RADIOKIT_Designer_Config__ ... */` comment block. As a result, downloading `RADIOKIT.h` via the API produces a file that cannot be re-imported into the RadioKit visual designer for round-trip editing.
2. **Limited Project Import**: The companion app's project import API endpoint does not flexibly accept both `.h` C++ header files and `.json` visual design configurations, requiring external tools or users to extract the JSON manually before posting.
3. **Marker Divergence**: The visual designer UI historically generated `/*__RadioKit_UI_Designer_Config__*/` while Arduino examples used `/*__RADIOKIT_Designer_Config__*/`.

## Proposed Solution
1. **Standardize Header Generation (`JsonArduinoGenerator`)**:
   - Provide `JsonArduinoGenerator.generateFullHeader(Map<String, dynamic> json)` that prepends the standard `/*__RADIOKIT_Designer_Config__\n<json>\nRADIOKIT_Designer_Config__*/` block to the generated C++ code.
   - Update `GET /api/designs/<id>/header` to return the complete, self-contained `RADIOKIT.h` file.
   - Unify `designer_screen.dart` to use the standardized generator.
2. **Unified Project Import API (`POST /api/designs/import` & `POST /api/designs`)**:
   - Accept either raw JSON design layouts or full `.h` file contents (or base64 payloads).
   - If `.h` content is provided, automatically extract the JSON comment block via flexible regex matching both `/*__RADIOKIT_Designer_Config__*/` and `/*__RadioKit_UI_Designer_Config__*/`.
   - Save the design into `DesignsProvider` and return parsed metadata.
3. **Robust Multi-Marker Header Parser**:
   - Update `HeaderFileParser` and `DesignerState.configPattern` to accept all case/naming variations of the comment block seamlessly.

## Impact & Benefits
- **Full Round-Trip Compatibility**: Any `RADIOKIT.h` generated by the app, downloaded via API, or taken from Arduino examples can be imported and edited directly.
- **Developer Experience**: External tools, CI/CD scripts, and automation can push either `.h` or `.json` directly into the app without format pre-processing.
