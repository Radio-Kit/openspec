## Context

The RadioKit Flutter app previously bundled the `rk-arduino` Arduino library as `assets/rk-arduino.zip` generated by `scripts/build-library-zip.sh` from an `rk-arduino/` directory in the same repo. After the `split-multirepo-setup` change moved `rk-arduino` into its own repository (`Radio-Kit/RK-Arduino`), the directory no longer exists in the RadioKit repo. Every release tag push now runs 5 multiplatform release workflows, all of which fail at the "Build library zip" step before `flutter build` is reached. The bundled zip has been unused at runtime beyond serving it back out to AI agents / test scripts via `/api/library/version` and `/api/library/download`.

## Goals / Non-Goals

**Goals:**
- Make all 5 release workflows build successfully on tag push.
- Stop bundling the Arduino library into the app.
- Give agents and test scripts a canonical way to obtain the Arduino library source.
- Remove the library code path cleanly from the app.

**Non-Goals:**
- Backward compatibility for `/api/library/*` (explicitly not needed — no external consumers).
- Publishing release assets from the `Radio-Kit/RK-Arduino` repo (out of scope; that repo already exists on GitHub and agents can browse/fetch it directly).
- Re-implementing library serving from a remote source.

## Decisions

### 1. Delete the bundling machinery
- **Choice**: Remove the "Build library zip" step from all 5 release workflows, delete `scripts/build-library-zip.sh`, drop `assets/rk-arduino.zip` from `pubspec.yaml`, and remove the `.gitignore` entry.
- **Rationale**: The zip is a build-time artifact for a directory that no longer lives in this repo. Deleting the dead step unblocks every release workflow.
- **Alternatives Considered**:
  - *Checkout `rk-arduino` in CI and keep bundling*: Keeps the fragile coupling and adds network dependency to every release build for no runtime benefit.
  - *Proxy the zip from a GitHub release*: Requirereleases/asset pipelines on the RK-Arduino repo that don't exist today; unnecessary complexity.

### 2. Remove the library service and API surface
- **Choice**: Delete `library_service.dart`; strip `LibraryService` from `remote_access_service.dart`, `remote_access_provider.dart`, and `remote_access_service_stub.dart`; remove the two routes and their handlers; drop the `/api/library/*` entries from `docs_service.dart`.
- **Rationale**: The endpoints only exist to serve the bundled zip. With no bundle, the service has nothing to do.
- **Alternatives Considered**:
  - *Keep endpoints as redirects to GitHub*: Adds a redirect hop with zero callers; the docs pointed at the repo URL make the redirect pointless.

### 3. Point docs at the canonical repository URL
- **Choice**: Replace library API documentation sections/rows with a pointer to `https://github.com/Radio-Kit/RK-Arduino`.
- **Rationale**: Agents need to know where to get the library source; the GitHub URL is the single source of truth and requires no app changes when the library evolves.
- **Note on duplicates**: `llm-docs/API.md` and `SKILLS/radiokit-remote/*` are duplicated into `assets/skills/`; both copies must be updated and kept in sync.

## Risks / Trade-offs

- **[Risk]** Agents relying on `/api/library/download` must switch to fetching from GitHub.
  → **Mitigation**: No known external consumers (endpoints documented only in app-internal docs/skills); acceptable per "no backward compatibility needed".
- **[Risk]** Duplicated docs (`API.md` ⇄ `assets/skills/llms.txt`, `SKILLS/*` ⇄ `assets/skills/*`) drift.
  → **Mitigation**: Update both copies in the same change and verify with a diff at the end.
- **[Risk]** A leftover reference to `LibraryService` breaks compilation.
  → **Mitigation**: Update all 4 Dart files that touch `LibraryService` (verified by targeted grep); run `flutter analyze` + tests before commit.

## Migration Plan

1. Edit the 4 release workflows (`android`, `ios`, `macos`, `windows`): remove "Build library zip" steps. For flatpak, remove the `bash scripts/build-library-zip.sh` command from the `flatpak/flatpak-flutter.yml` manifest build-commands (the `release-linux-flatpak.yml` workflow itself never had a bundling step — the failure came from the manifest).
2. Delete `scripts/build-library-zip.sh`; remove pubspec asset + `.gitignore` entry.
3. Delete `library_service.dart`; strip it from the 3 Dart files.
4. Remove `/api/library/*` entries from `docs_service.dart`.
5. Update `llm-docs/API.md` + `assets/skills/llms.txt` and `SKILLS/radiokit-remote/SKILL.md` + `assets/skills/radiokit-remote.md` with the repo URL.
6. Grep for residual `LibraryService` / `rk-arduino.zip` / `/api/library` references; `flutter analyze`; run tests.
